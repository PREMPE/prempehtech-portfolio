Microsoft Entra Hybrid Identity

Designed and implemented a hybrid identity environment connecting an on-premises Active Directory domain to Microsoft Entra ID using Microsoft Entra Connect Sync. The project included custom-domain integration, routable UPN configuration, directory synchronization, identity validation, and successful authentication using a synchronized hybrid identity.

Microsoft Entra ID Active Directory Entra Connect Hybrid Identity Windows Server DNS Identity Management VMware
01

Project Overview

This project extends a traditional on-premises Active Directory environment into Microsoft Entra ID to create a functional hybrid identity architecture.

The on-premises environment used the internal corp.local Active Directory domain. A verified public domain, prempehtech.ca, was introduced as an alternative User Principal Name suffix so identities could use a cloud-routable sign-in name while remaining managed from the local Active Directory environment.

Microsoft Entra Connect Sync was then deployed to synchronize selected Active Directory identities into the Microsoft Entra tenant. The completed environment demonstrated that an identity created and managed on-premises could be represented in Entra ID and used for cloud authentication.

03

Preparing Active Directory for Hybrid Identity

The internal Active Directory namespace used corp.local. Because this is not a publicly routable domain, I configured prempehtech.ca as an alternative UPN suffix in Active Directory Domains and Trusts.

This allowed local users to retain their Active Directory accounts while receiving a cloud-compatible sign-in name such as:

user@prempehtech.ca
04

Microsoft Entra Custom Domain Integration

The same public namespace used for the Active Directory UPN was added to Microsoft Entra ID as a custom domain. Domain verification established that the tenant could use prempehtech.ca for synchronized identity names.

Why this matters: matching the on-premises UPN suffix with a verified Microsoft Entra domain creates a consistent identity namespace across the local and cloud environments.
05

On-Premises Identity Configuration

An Active Directory user was configured with the @prempehtech.ca UPN suffix. The account remained an on-premises Active Directory object while receiving an identity format suitable for synchronization into Microsoft Entra ID.

06

Microsoft Entra Connect Deployment

Microsoft Entra Connect Sync was installed on the Management server. This system became the synchronization component responsible for connecting the local Active Directory environment with Microsoft Entra ID.

07

Directory Synchronization

After the local directory and Microsoft Entra tenant were connected, Entra Connect completed its configuration and initiated the synchronization process.

The synchronization configuration linked the on-premises identity source with the cloud tenant while maintaining the relationship between the original Active Directory object and its corresponding Microsoft Entra identity.

08

Synchronized Identity Validation

After synchronization, the Active Directory identity appeared in Microsoft Entra ID using the prempehtech.ca namespace.

This validated that the account had successfully moved through the hybrid identity synchronization path from the local directory into Microsoft Entra ID.

09

On-Premises Attribute Verification

I further validated synchronization by inspecting the Microsoft Entra properties associated with the identity. The cloud object displayed information linking it back to the original Active Directory account.

Visible synchronized information included the on-premises distinguished name, SAM account name, security identifier, User Principal Name, domain name, immutable ID, synchronization state, and last synchronization timestamp.

Validation result: the presence of the on-premises directory attributes demonstrates that the Microsoft Entra object is tied to the synchronized Active Directory identity rather than being an unrelated cloud-only account.
10

Cloud Authentication Validation

The final functional test was authentication using the synchronized hybrid identity.

The synchronized prempehtech.ca account successfully authenticated to the Microsoft Entra environment, completing the identity path from an on-premises Active Directory account to a usable cloud identity.
